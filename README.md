# Healthcare Claims Analytics API

Enterprise-style healthcare claims analytics backend built with Java 17, Spring Boot, Spring Data JPA, and PostgreSQL.

Project demonstrates backend API development, CSV data ingestion, layered architecture, 
native SQL analytics queries, DTO-based responses, and database-backed healthcare claims processing.


## Tech Stack

- Java 17
- Spring Boot
- Spring Data JPA
- PostgreSQL
- Apache Commons CSV
- Maven

## Architecture

```text
Controller → Service → Repository → PostgreSQL
```

## Main Packages
controller/   REST API endpoints
service/      Business logic, CSV ingestion, analytics processing
repository/   JPA database access and native SQL queries
model/        JPA entities
dto/          API response DTOs

## Performance Engineering Extension

This project also includes a SQL performance-engineering extension documented in:

[`PROJECT_2_PERFORMANCE.md`](./PROJECT_2_PERFORMANCE.md)

The extension benchmarks PostgreSQL analytics queries using `EXPLAIN ANALYZE`, compares execution plans before and after indexing, and documents when indexes improved query performance versus when PostgreSQL kept the original sequential scan plan.

Key findings:
- Grouped `COUNT(*)` queries on `state` and `provider_id` improved with index-only scans.
- The `status` index was not used due to low cardinality.
- A composite `(state, claim_amount)` index did not improve the full-table `SUM(claim_amount)` aggregation.

## Endpoints

### Get Claims

```http
GET /claims
```

Returns claim records currently stored in the database.

---

### Upload Claims CSV

```http
POST /claims/upload
```

Accepts a CSV file using multipart form-data.

Form-data key:

```text
file
```

Example curl command:

```bash
curl.exe -X POST -F "file=@claims.csv" http://localhost:8080/claims/upload
```

Example response:

```json
{
  "success": true,
  "rowsInserted": 2,
  "message": "Claims uploaded successfully"
}
```
Data is uploaded transactionally. All entries must be valid or none are uploaded.


---

### Claims Count by State

```http
GET /claims/analytics/by-state
```

Example response:

```json
[
  {
    "state": "CA",
    "claimCount": 2
  }
]
```
Returns State & how much claims tied to the state



---

### Claims Count by Status

```http
GET /claims/analytics/by-status
```

Example response:

```json
[
  {
    "status": "APPROVED",
    "claimCount": 5
  }
]
```
Returns the # of claims with said status


---

### Total Claim Amount by State

```http

```

Example response:

```json

  {
```

---

### Top Providers by Claim Count

```http

```


## CSV Format

Example CSV:

```csv
patient_id,provider_id,state,claim_amount,status
P001,PR001,CA,1200.50,APPROVED
P002,PR002,NY,850.00,DENIED
```

Required fields:

```text
patient_id
provider_id
state
claim_amount
```

Optional fields may include:

```text
diagnosis_code
procedure_code
status
```

## Database Notes

The `claims` table uses an auto-generated primary key:

```sql
claim_id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

The application uses:

```java
@GeneratedValue(strategy = GenerationType.IDENTITY)
```

to allow PostgreSQL to generate claim IDs automatically sequentially relative to the latest claim id.

Database uses Transactional data entry to guarantee all entries are valid before uploading.
